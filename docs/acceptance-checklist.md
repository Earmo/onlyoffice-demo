# 验收清单

这份清单承接自动化验证之外的关键人工核对路径，适合交付前最后走一遍。

## 1. 自动化基线

- [ ] 在仓库根执行 `npm run verify`
- [ ] 确认后端测试通过
- [ ] 确认前端 Vitest 通过
- [ ] 确认前端构建通过
- [ ] 确认 `docker compose config` 通过

## 2. 工作台与编辑页

- [ ] 打开 `/` 能先看到文档工作台，而不是直接进入固定文档
- [ ] 首页能看到当前租户 / 当前用户轻量上下文提示
- [ ] 新建、上传、导入入口都可见
- [ ] 创建成功后结果会回到列表并高亮，而不是强制直接跳编辑页
- [ ] 进入 `/editor/{documentId}` 后能看到返回列表入口
- [ ] 编辑页切换文档时会先弹确认
- [ ] 点击“保存并返回”后不会因为额外轮询 `save-status` 明显卡顿

## 3. ONLYOFFICE 与分布式链路

- [ ] `editor-config` 能正常生成
- [ ] `document.url` 与 `callbackUrl` 由后端生成，前端不自行拼接
- [ ] callback JWT 配置正确时保存链路正常
- [ ] callback JWT 配置错误时接口能返回明确错误，而不是静默成功
- [ ] `save-status` 能看到当前摘要状态和最近事件
- [ ] 编辑页关闭后即使 ONLYOFFICE 继续补发关闭类 callback，列表状态也不会错误停留在 `editing`

## 4. 存储与安全边界

- [ ] MinIO 作为正式默认策略时，文档上传、下载、回写都正常
- [ ] 远程导入和图片代理对私网、超大响应、错误媒体类型会明确拒绝
- [ ] `storageAvailable=false` 的文档仍能在列表看到异常状态，而不是被静默隐藏

## 5. 文档交付面

- [ ] README 已说明根级验证命令和推荐执行顺序
- [ ] 独立部署说明可支撑完整服务落地
- [ ] 微服务接入说明可支撑上游系统 API-first 接入
- [ ] 配置矩阵能说明关键环境变量的默认值、必填性和适用场景
- [ ] 新接手的人无需阅读 `.planning` 也能完成一次完整验证
