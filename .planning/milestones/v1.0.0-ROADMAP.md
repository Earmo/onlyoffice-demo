# Milestone v1.0.0: OnlyOffice Document Service

**Status:** ✅ SHIPPED 2026-04-08
**Phases:** 1-12
**Total Plans:** 36

## Overview

这个里程碑把仓库从最小 ONLYOFFICE 集成示例推进成可独立部署、也可嵌入上层系统的文档编辑服务。交付范围覆盖服务边界、共享元数据、可插拔存储、低耦合用户上下文、文档工作台、分布式编辑链路、自动化验证与交付文档，并在后半程完成模块化、环境拆分、COS、预览/编辑工作台优化、Element Plus 重构、服务端分页、逻辑删除和最近文档排序等增强。

## Milestone Summary

### Key Accomplishments

1. 服务配置、运行时 URL 与共享主数据已经从 demo 形态升级为可独立部署的分布式文档服务基线。
2. MinIO 与腾讯云 COS 都已接入统一存储抽象，上传、导入、回写和 provider 路由形成闭环。
3. 用户上下文、预览/编辑分流、编辑会话生命周期和列表“编辑中”状态已经收敛到明确的服务端真相源。
4. 工作台首页、创建入口、文档列表、服务端分页、逻辑删除和最近文档排序已经构成完整用户流程。
5. 前端主要页面已经切到 Element Plus 组件体系，后端 starter 命名、模块边界与环境配置也同步完成收口。
6. 根级 `npm run verify`、接入文档与 compose 配置都已通过，仓库具备稳定的本地验证与交付入口。

### Key Decisions

- 使用 `publicBaseUrl` / `internalBaseUrl` / `documentServerUrl` 的分离运行时地址模型。
- 以共享数据库元数据和统一存储策略承接分布式编辑服务的真相源。
- 用户体系只做低耦合上下文注入与适配，不在 v1 直接扩展复杂权限平台。
- 前端 UI 在 v1 后半程收口到 Element Plus，降低自定义样式维护成本。

### Issues Resolved

- 解决了 demo 单页入口无法承载真实列表/上传/预览/编辑流程的问题。
- 解决了本地目录推导文档状态、分布式部署下回写路径脆弱的问题。
- 解决了旧运行事件滞留导致列表编辑状态失真的问题。
- 解决了根级验证入口断言过期导致的后端测试失败问题。

### Issues Deferred

- 阿里云 OSS provider 仍留在后续里程碑。
- 更细粒度的 document-scoped authorization 仍需单独作为后续 requirement 规划。
- 更复杂的权限、历史版本与 webhook 能力留待 v2 范围。

### Technical Debt

- Maven repository id 命名警告仍需后续在环境/团队配置层清理。
- Mockito 动态 agent 警告仍在，后续 JDK 升级前需要显式配置 agent。
