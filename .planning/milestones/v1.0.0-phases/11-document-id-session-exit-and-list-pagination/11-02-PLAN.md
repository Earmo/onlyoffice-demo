# Plan 11-02: 后端驱动的文档列表分页与筛选契约

## Outcome

把文档工作台从“全量加载 + 页面层持有查询状态”改造成“后端分页查询 + 页面只渲染当前页”的稳定列表接口，为后续文档量增长和状态收敛提供统一入口。

## Notes for Execution

- 分页不是单纯给响应多加 4 个字段；要同时收口“筛选在哪执行”和“当前页数据由谁决定”。
- `storage` 过滤不容易下沉到数据库，因此执行时要优先保证结果正确与 total 正确，而不是勉强走一个错误的数据库分页路径。
