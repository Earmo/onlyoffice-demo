    实现中 bucket 名统一来自 `onlyoffice.integration.storage.minio.bucket`；
    发生对象不存在时，`exists` 返回 `false`，`read` 抛出明确异常，不能吞掉错误并伪装成空文件。
    同时补齐 `MinioDocumentStorageStrategyTest`，使用 Testcontainers 启动 MinIO，验证写入、读取、覆盖和删除四个核心动作。

    把核心业务写入语义切到 MinIO-aware 的统一存储路径。具体要求：
    1. `storeUploadedDocument`、`importRemoteDocument`、`createNativeDocument` 先通过当前 provider 写入对象，再创建元数据；若元数据创建失败，立即调用 `delete(storageKey)` 做补偿清理；
    2. 若对象写入失败，禁止写入元数据；
    3. `saveCallbackDocument` 先下载 ONLYOFFICE 返回的字节，再调用 `overwrite` 覆盖原对象；若下载失败或覆盖失败，旧对象必须保持可读；
    4. `DocumentController.callback` 的失败路径继续调用 `documentStatusService.recordSaveFailed(...)`，成功路径继续标记 `saved`。
    同时新增 `DocumentControllerTest`，至少覆盖 `status=2` 成功回写、回写异常时标记失败、旧版本内容仍可读取三条路径。
