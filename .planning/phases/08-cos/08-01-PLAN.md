# Plan 08-01: 拆分 dev/test/prod 配置并收敛构建命名

## Outcome

把后端运行配置从“单一大配置文件 + 零散本地覆盖”升级成正式的环境模型，同时修正 `starter` 与 `service` 的 Maven 坐标语义，让后续 COS 和 service 接口化建立在清晰的构建与配置边界上。

  <action>
    把后端配置正式拆分为 `dev / test / prod` 三个环境，并让 `application.yml` 负责统一入口选择。
    具体目标状态：
    1. `application.yml` 保留共享配置，并显式声明 `spring.profiles.active: ${SPRING_PROFILES_ACTIVE:dev}`；
    2. 新增 `application-dev.yml`，承接本地开发默认数据库、local/minio 默认值、非生产级远程资源限制和默认地址；
    3. 新增 `application-test.yml`，承接测试环境数据库、测试存储根目录、测试 document server 地址和更适合测试的默认值；
    4. 新增 `application-prod.yml`，承接生产环境必须显式提供的数据库地址、公开/内部地址、MinIO/COS 凭证占位和严格安全默认值；
    5. `application-windows-debug.yml` 继续存在，但要明确它是 Windows 本地断点调试覆盖层，不替代 `dev / test / prod` 三个正式环境；
    6. 每个配置项都保留或补足中文注释，尤其是 profile 选择、对象存储、ONLYOFFICE 地址、安全开关和访问上下文字段。
  </action>
  <verify>`cd packages/server && mvn -q -pl onlyoffice-integration-service -am -DskipITs -Dtest=OnlyofficeIntegrationPropertiesTest -Dsurefire.failIfNoSpecifiedTests=false test`</verify>

    <criterion>`packages/server/onlyoffice-integration-service/src/main/resources/application.yml` contains `spring.profiles.active`</criterion>
