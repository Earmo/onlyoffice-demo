# Phase 14.1 / Plan 01 Summary

**后端已经具备文档维度的 runtime-events SSE 通道，能够推送初始保存状态、keepalive 和后续运行态更新，并为前端的 fetch-based stream 接入提供稳定契约。**

## Accomplishments

- `DocumentController` 已新增 `GET /api/documents/{documentId}/runtime-events`，使用与 heartbeat/close 相同的访问上下文解析方式，并在打开流前刷新编辑会话存活时间。

- `DocumentControllerTest` 与 `DocumentRuntimeEventStreamServiceImplTest` 已覆盖 endpoint 契约、document-scoped publish、keepalive liveness 与 subscriber cleanup。
- `packages/server/pom.xml` 已允许 targeted `-Dtest` 在多模块执行时跳过无匹配测试模块，便于 phase 级验证。

## Decisions Made

- 用共享 `ScheduledExecutorService` 驱动 keepalive，而不是 `@Scheduled`，这样 Phase 14.1 不需要额外启用 scheduling infrastructure。
- subscriber cleanup 不只移除 subscriber，还要移除空的 `documentId` bucket，避免 registry 长期泄漏空 key。
- clean server-side completion 被视为预期行为的一部分，交给前端立即重连，不把它等同于运行态错误。
