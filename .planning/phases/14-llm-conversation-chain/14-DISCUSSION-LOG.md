## 模型接入契约

| Question | Selected | Notes |
|--------|----------|-------|
| 后端如何对接上游模型？ | 做成可切换的策略模式，默认策略采用标准 OpenAI 接口方法 | 不把 Phase 14 锁死在单一厂商 SDK 上。 |
| 前端对后端的响应形状要多“透明”？ | 不透传原始响应，但 DTO 里保留 `usage / finishReason / providerResponseMeta` | 用户先给了相互冲突的偏好，后续收敛到“折中 DTO”。 |
| AI 配置放在哪？ | 独立配置根 `llm.*` | 不继续挂在 `onlyoffice.integration.ai` 下。 |
| 浏览器能否看到厂商细节？ | 不能拿到上游原始响应，只看本项目 DTO | `providerResponseMeta` 允许存在，但不是完整 raw payload。 |
| AI 未配置或被禁用时怎么表现？ | 抽屉保留可见；输入区禁用；给出明确提示 | 提示既在输入框上方，也在消息空态中出现。 |

**Notes:** 这一轮讨论把旧上下文里“`onlyoffice.integration.ai` 配置块”和“极简 DTO”两条假设都放开后重定了。

## 对话上下文边界

| Question | Selected | Notes |
|--------|----------|-------|
| 发送时上下文基准是什么？ | 每次发送都绑定“当前抓取的明确快照” | 不是发送时再临时读取编辑器。 |
| 同一会话里重新抓新选区怎么办？ | 弹确认：新开会话或继续当前会话 | 不做静默切换。 |
| 没抓到选区还能不能首轮提问？ | 可以，但显式标记“无选区上下文” | 之后又补充：空选区也算明确快照。 |
| 章节目录和模型 payload 的关系？ | 自动把当前活跃章节标题一起带给模型，但界面要明显提示且可主动取消 | 相比旧上下文，这是明确变更。 |
| 发送前要不要再确认一次上下文？ | 不需要，预览区显示什么就发什么 | 发送不再多一道确认。 |
| “无选区上下文”算不算明确快照？ | 算 | 需要显式记录 `selection = empty`。 |

**Notes:** 旧上下文里“没有成功抓取选区则不允许首轮提问”的约束被放开，改成允许空快照参与请求。

## 会话状态与记忆策略

| Question | Selected | Notes |
|--------|----------|-------|
| 会话保留范围？ | 后端持久化到文档维度 | 讨论中明确指出这比旧上下文更强，会影响模型与接口设计。 |
| UI 默认展示多少轮？ | 最近 6 轮 | 不要求默认展示整条长线程。 |
| 发给模型的历史怎么裁？ | 不锁死轮数，按模型上下文预算动态裁剪 | 先前一度考虑固定轮数，最终改为动态预算。 |
| 同一时刻请求并发怎么处理？ | 允许用户强制中断上一条再发下一条 | 比“严格单飞”更强。 |
| 失败后重试语义？ | 点击重试前先确认本次重试上下文 | 不做静默复发。 |
| 新建会话后旧消息怎么处理？ | 当前页面可切回旧线程 | 不清空、不覆盖。 |
| 重新打开同一文档时默认行为？ | 默认新建空会话，但可手动打开旧会话 | 不自动恢复最近会话。 |
| 强制中断后，占位消息怎么处理？ | 保留用户问题，assistant 占位改成“已取消” | 不直接移除这轮痕迹。 |

**Notes:** 这一组彻底推翻了旧上下文里“当前编辑页内存态、不做持久化”的假设。

## 抽屉交互与响应呈现

| Question | Selected | Notes |
|--------|----------|-------|
| 主布局怎么排？ | 上方上下文卡片 + 中间消息列表 + 底部输入框 | 不切独立页面。 |
| 选区和目录怎么摆？ | 选区常驻显示；目录单独放次级 tab | 与当前三段式准备态不同。 |
| 会话入口放哪？ | 消息区左上角二级入口 | 不放顶栏 tab。 |
| 发送中状态如何表现？ | 仅顶部状态条和发送按钮 loading | 不预插 assistant 占位。 |
| 失败态如何表现？ | 只在线程内显示失败消息卡和重试按钮 | 不额外做顶部全局告警。 |
| 扩展信息默认怎么展示？ | 每条 assistant 消息下默认展示简短摘要 | 包括 `usage / finishReason / providerResponseMeta`。 |
| AI 未配置的提示放哪？ | 两处都要：输入框上方固定提示条 + 消息区空态卡片 | 这与第一组决策联动。 |
| 发送中时消息区还要不要额外提示？ | 不要，顶部状态条 + 底部按钮 loading 就够了 | 消息列表保持稳定，不加加载行。 |
| 抽屉宽度如何调整？ | 右侧抽屉拓宽到当前大小的两倍左右 | 约从 `400px` 心智扩大到 `800px`。 |

**Notes:** 用户额外追加了“抽屉占位拓宽到当前大小两倍”的 UI 决策，这不是最初灰区列表里的默认项，但已明确纳入实现要求。

## 接口组织与工程边界

| Question | Selected | Notes |
|--------|----------|-------|
| 后端 AI 接口挂哪？ | 独立 `/api/llm/...`，请求体里再带 `documentId` | 不继续塞进 `/api/documents/*`。 |
| 会话模型怎么组织？ | 一个文档多个会话，会话下多条消息 | 与文档级持久化一致。 |
| 前端模块怎么拆？ | 单独拆 `EditorAiWorkbench.vue` 子组件，由 `EditorShell.vue` 挂载 | 壳层与 AI 工作台职责分离。 |
| 中断请求的后端语义？ | 后端也维护可取消请求，并尽量向上游发取消 | 不只是前端本地取消。 |
| `providerResponseMeta` 允许到什么粒度？ | 基本不限制，除了密钥都可下发 | 但仍通过本项目 DTO 输出，不是完整 raw payload。 |
| `llm.*` 配置根与现有 onlyoffice 配置关系？ | `llm.*` 顺带收 AI 会话策略配置 | 包括启用开关、默认历史策略、超时等。 |
| 自动化验证至少覆盖到哪？ | 至少一条接近真实链路的 E2E/联调验证 | 高于纯 DTO/service 单测。 |

**Notes:** 这组让旧的 Phase 14 计划天然失效，因为旧计划建立在“文档内路由、内存态对话、较轻 DTO”假设上。
